Catalogue Module API Specification

Platform: SalaryNeeds Backend • Base URL: https://salary.hinchmart.com • Roles: Admin, User, Worker • Version: 1.0.0

1. System Architecture & Hierarchy

The catalogue system implements a unified 3-tier hierarchy representing a single source of truth across all roles:

Hierarchy: Category (Tier 1) → Subcategory / Service (Tier 2) → Optional Variant (Tier 3)
Single Source of Truth: Admin manages the catalogue. Both User and Worker applications read from the same database tables (categories, services, variants). No duplicate records are created for User or Worker.

2. Authentication & Role Authorization

Role Header Passed Permissions & Access
ADMIN X-Role: ADMIN Full CRUD access to /api/admin/**, plus read access to all catalogue views.
USER X-Role: USER Read-only access to active catalogue via /api/user/**. Cannot access Admin APIs (403 Forbidden).
WORKER X-Role: WORKER Read-only access to active catalogue via /api/worker/**. Cannot access Admin APIs (403 Forbidden).

3. Admin Catalogue APIs (Management)

Admin endpoints allow creating, updating, activating, and deleting categories, subcategories, and variants.

POST Create Category (with Image Upload)
https://salary.hinchmart.com/api/admin/categories

Content-Type: multipart/form-data

Form-Data Parameters:

  • name (Text, Required): Category name (e.g. Home Cleaning)
  • description (Text, Optional): Category description
  • amount (Number, Optional): Base amount (default 0.00)
  • discount (Number, Optional): Discount value (default 0.00)
  • displayOrder (Number, Optional): Sort order (default 0)
  • status (Text, Optional): ACTIVE or INACTIVE
  • image (File, Optional): Direct image file upload (.png, .jpg, .webp)
POST Create Subcategory (with Image Upload)
https://salary.hinchmart.com/api/admin/subcategories

Content-Type: multipart/form-data

Form-Data Parameters:

  • categoryId (Text, Required): Parent Category UUID
  • name (Text, Required): Subcategory name (e.g. Kitchen Cleaning)
  • description (Text, Optional): Detailed description
  • amount (Number, Required): Base price (e.g. 1500.00)
  • discount (Number, Optional): Discount (e.g. 10.00)
  • status (Text, Optional): ACTIVE or INACTIVE
  • image (File, Optional): Subcategory image file
POST Create Optional Variant (with Image Upload)
https://salary.hinchmart.com/api/admin/subcategories/{subcategoryId}/variants

Content-Type: multipart/form-data

Form-Data Parameters:

  • name (Text, Required): Variant name (e.g. 1 BHK, 2 BHK)
  • description (Text, Optional): Specific description
  • amount (Number, Required): Variant price (e.g. 1500.00)
  • discount (Number, Optional): Discount value (e.g. 10.00)
  • status (Text, Optional): ACTIVE or INACTIVE
  • image (File, Optional): Variant image file

5. Worker Catalogue APIs (Worker View)

All Worker APIs require X-Role: WORKER and read the identical active catalogue dataset from the same database.

Method Endpoint Description
GET /api/worker/categories Retrieve all active categories for worker partner app.
GET /api/worker/categories/{categoryId}/subcategories Retrieve all active subcategories under selected category.
GET /api/worker/subcategories/{subcategoryId} Retrieve full details of a specific subcategory.
GET /api/worker/subcategories/{subcategoryId}/variants Retrieve active variants (returns [] if none exist).
